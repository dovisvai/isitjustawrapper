# Operations

How this site is hosted and kept running, written for whoever maintains it — and published rather than kept internal,
because a project that asks other people to show their working should show its own.

If you are here to **add or correct an entry**, you want [CONTRIBUTING.md](../CONTRIBUTING.md) instead. If you are here
because you are **forking this** to run a directory of your own, this page is the whole operational picture.

---

## The mental model

Three places are involved. The flow only ever goes one direction.

```
  your laptop  ────push───▶  GitHub  ────auto-deploy───▶  Cloudflare Pages
  (you edit)                 (the record)                 (what the public sees)
```

| Place | What it holds | Why it exists |
| --- | --- | --- |
| **Your laptop** | Where you edit. `npm run admin`, `npm run dev` | Where the work happens |
| **GitHub** | Every change as a dated commit, plus the weekly price robot | **This is the audit trail.** A dated, attributed, reviewable history of every price claim is what makes publishing this defensible |
| **Cloudflare Pages** | The live site | Free static hosting, plus the small amount of server needed for stats and sponsor clicks |

**Nobody edits the live site.** You change files locally, commit, push, and Cloudflare rebuilds on its own. If you ever
find yourself wanting to edit something in a web form, that is the instinct this project is deliberately built to
frustrate — see "Why there is no web admin panel" in the [README](../README.md).

## Part 1 — One-time setup

> **Steps 1–4 are already done for isitjustawrapper.com.** They are kept here because they are the steps you would
> repeat if you forked this, moved hosts, or had to rebuild from scratch — and because a runbook that only documents
> the parts you have not done yet is not a runbook. Skip to Step 5 if you are setting up hosting now.

### 1. Make it a repository

```bash
git init -b main
```

```bash
git add . && git commit -m "Initial commit: Is it just a wrapper?"
```

### 2. Push it to GitHub

Start private. Go public only once the prices are verified — there is no rush to publish numbers about named
businesses before anyone has checked them.

```bash
gh repo create isitjustawrapper --private --source=. --push
```

No `gh` installed? Create the repo at github.com and follow its "push an existing repository" instructions.

### 3. Verify every price

This is the real work, and it has to happen before anything goes public. It is also not a one-time event — the weekly
watcher can send entries back here at any point.

```bash
npm run admin:verify
```

It walks the entries riskiest-first, opens each pricing page in your browser, and asks one question. Budget 30–40
minutes.

**Check the billing period, not just the number.** Annual-versus-monthly is the mistake most likely to produce an
angry email, because it can double a multiple.

Some will not resolve from a fetch at all, and those are the ones to slow down on:

- **Vendors that block automated requests** — ChatGPT, Midjourney and Perplexity all return 403 to the watcher. Open
  the pages yourself; the watcher will keep reporting `unreachable` and that is expected, not a fault.
- **Pages that render prices in JavaScript** — Grammarly, Rytr, ChatPDF, Gamma, Lovable, QuillBot and Wordtune. Those
  entries declare `priceCheck.automatable: false` so the weekly job does not demote them on a false alarm.
- **Vendors that price by region** — ChatPDF and QuillBot both serve different currencies by location. The site
  records the US list price and says so in the billing note.

Then:

```bash
npm run check:publish
```

When that passes you are publishable. Until then it fails, and that is the seatbelt doing its job.

```bash
git add -A && git commit -m "Verify seed prices against vendor pricing pages" && git push
```

### 4. The domain — done

The site is wired to **isitjustawrapper.com**. Four files carry that origin, and they have to agree:

| File | Setting | What it affects |
| --- | --- | --- |
| `astro.config.mjs` | `site:` | Canonical URLs and the sitemap |
| `wrangler.toml` | `SITE_ORIGIN` | The UTM tags on sponsor outbound links |
| `public/robots.txt` | `Sitemap:` | What search engines are told |
| `scripts/watch-prices.ts` | `USER_AGENT` | What a vendor sees in their logs when we fetch their pricing page |

If the domain ever changes, change all four together. The last one points at `/methodology` on purpose: a vendor whose
pricing page gets fetched every week should land somewhere that explains what this is and how to file a correction,
rather than on a git host.

The sitemap is generated by `@astrojs/sitemap` at `/sitemap-index.xml`.

### 5. Connect Cloudflare Pages

Cloudflare dashboard → **Workers & Pages** → **Create** → **Pages** → **Connect to Git** → select the repo.

| Setting | Value |
| --- | --- |
| Build command | `npm run check:publish && npm run build` |
| Build output directory | `dist` |
| Environment variable | `NODE_VERSION` = `22` |

> ### Get the build command right
>
> The obvious choice — `npm run build` — **skips the publication gate**. It validates the data but does not check
> whether a human confirmed the prices, so it would cheerfully put unverified claims about named companies online.
>
> Use `npm run check:publish && npm run build` so a deploy **fails** rather than publishing something nobody checked.
> This single line is the difference between the safety system working and being decorative.

### 6. Publish traffic on /stats

`/stats` shows Cloudflare's own zone analytics — daily page views and unique visitors — read server-side through the
GraphQL Analytics API. Nothing is added to the site to collect them.

1. **Create an API token.** Cloudflare dashboard → **My Profile → API Tokens → Create Token → Custom token**.
   Permission: **Zone → Analytics → Read**. Zone resources: **Include → Specific zone → isitjustawrapper.com**.
   Nothing else — this token can read traffic totals and do nothing more.
2. **Copy the zone id** from the domain's **Overview** page (right-hand column, "Zone ID").
3. **Add both to the Pages project:** **your project → Settings → Variables and Secrets**, Production:
   - `CF_API_TOKEN` — type **Secret**, the token from step 1
   - `CF_ZONE_ID` — type **Text**, the zone id
4. **Redeploy** (Deployments → latest → Retry deployment). Variables only reach functions on a new deployment.

The token never goes in the repository. Without these, the site works normally and `/stats` says traffic figures are
not configured, rather than showing numbers it does not have.

**Sponsor clicks (optional, only once a slot is sold).** Clicks are the one thing counted by the site itself, on the
`/go/<slot>` redirect. Create a KV namespace with `npx wrangler kv namespace create STATS` and bind it under
**Settings → Bindings → KV namespace**, variable name `STATS`. Until then the sponsor-clicks tile reads "—".

### 7. Let the weekly robot file its findings

GitHub repo → **Settings → Actions → General → Workflow permissions** → tick
**"Allow GitHub Actions to create and approve pull requests."**

Without this the price watcher still runs and still fails loudly, but cannot open the pull request that tells you what
changed.

### 8. Go public

Make the repo public when you are ready. The data is CC BY and the code is MIT; the repository being readable is part
of the credibility.

## Part 2 — The weekly rhythm

Most weeks you do nothing.

Every Monday at 06:17 UTC the robot re-fetches every cited pricing page and every rate card. If nothing moved, you hear
nothing.

### When it finds something

You get a pull request titled **"Price watch: pricing pages changed."** Affected entries have already been demoted to
`unverified`, which means **the site stops deploying until you look.** That is intentional: a stale price should come
down by itself, not wait for you to notice.

```bash
git pull
```

```bash
npm run admin:verify
```

```bash
git add -A && git commit -m "Re-verify prices flagged by price watch" && git push
```

Cloudflare rebuilds itself. Do not merge the robot's pull request by reading the diff alone — open the pages.

### Adding a product

```bash
npm run admin:new
```

Then verify it, commit, push. Same three steps as everything else.

### Where do I stand?

```bash
npm run admin
```

### A quarterly habit worth keeping

Check the rate card. If model prices have moved, updating `data/rates.json` changes **every** estimate on the site in
one commit. It is the highest-leverage maintenance there is, and the easiest to forget because nothing breaks visibly
when it goes stale.

## Part 3 — When a vendor emails you

Mail arrives at **office@isitjustawrapper.com**, which is published in the site footer, on the methodology page, on
the corrections log and in the code of conduct. It is a plain `mailto:` rather than a form on purpose — a reference
that is awkward to reach is a reference nobody corrects.

This will happen. Speed and openness are most of your defence.

1. **Reply within a day.** A fast, plain answer defuses almost everything.
2. **If they are right about a fact** — wrong price, wrong tier, wrong billing term — fix it immediately and without
   argument:

   ```bash
   npm run admin:price
   ```

   That updates the entry *and* writes the public corrections log entry for you. Then commit and push.
3. **If they dispute the verdict**, that is opinion, not fact. You are not obliged to change it. Offer to publish their
   position on the entry. Consider it seriously; the site is better when it is argued with.
4. **Never quietly edit.** The corrections log is what makes this a reference rather than a target. Publishing your own
   mistakes is the entire point of having the page.

Everything you need to stand behind is already written down on `/methodology`: the estimates are labelled estimates,
the assumptions are stated, the rates are dated and sourced, the multiples are floors rather than ceilings, and
"wrapper" is defined as an architecture rather than an accusation. Re-read it before replying to anyone.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| Deploy fails: `verification.status is "unverified"` | Working as designed — something is unchecked | `npm run admin:verify`, commit, push |
| Deploy succeeded but you did not verify anything | Build command is `npm run build` | Change it to `npm run check:publish && npm run build` |
| `/stats` says traffic figures are not configured | No `CF_API_TOKEN` / `CF_ZONE_ID` | Step 6, then redeploy |
| `/stats` shows an "Authentication error" or similar | Token lacks Zone → Analytics → Read on this zone | Recreate the token, step 6 |
| Traffic numbers look high | Cloudflare counts every HTML response, including some bots | Expected; the page says "approximate" |
| Price watch runs but no pull request appears | Actions cannot open PRs | Step 7 |
| Watcher reports `unreachable — HTTP 403` | The vendor blocks bots | Check that one by hand; it will not self-resolve |
| Watcher reports `price-missing`, prices "none detected" | Page renders prices in JavaScript | Check by hand. The watcher reports what it can see, not what it guesses |
| Build fails on an old Node | Cloudflare default | Set `NODE_VERSION` = `22` |
| Theme toggle, filters or calculator dead **in production only** | The CSP blocked the inline scripts | `npm run build` must run `scripts/csp-hashes.ts`; check `dist/_headers` contains `sha256-` entries |
| A sponsor link 404s | Slot is not filled in `data/sponsors.json` | `npm run admin:sponsor` |
| `npm run dev` shows no stats | Pages Functions do not run under `astro dev` | `npm run dev:functions` |

## Running costs

| Item | Cost |
| --- | --- |
| Cloudflare Pages | Free at any traffic this site will plausibly see |
| Cloudflare analytics API | Free; responses are cached for ten minutes |
| GitHub Actions | Free for a public repository |
| Domain | Roughly $10–15 a year |

The site is cheap to run and cheap to leave running. The expensive part is attention, and the price watcher exists to
keep that cost near zero until something actually needs you.

## The one rule

**The site cannot go live with a price you have not personally looked at.**

Everything else here is recoverable. That one is not, because it is the only thing on the site that could be described
as a false statement of fact about a named business. The tooling is built so that following this rule is the path of
least resistance — but the tooling can be switched off by one careless build command, so keep an eye on Step 5.
